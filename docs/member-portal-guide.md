## 成员怎样使用

1. 管理员将您的邮箱绑定到本人名册后，用该邮箱请求登录验证码并在工作台输入。验证码请求成功不代表邮件已经送达；收不到时先检查垃圾邮件，再联系管理员核对邮箱和邮件配置。
2. 填写个人介绍、研究兴趣和教育经历，中文优先、英文可选。姓名、身份、分组和在读状态由管理员通过名册维护，成员不能改成另一人。
3. 添加最多 3 项科研项目，用简短文字说明科学问题、研究思路、本人工作和可公开进展。配图可用 JPEG、PNG 或 WebP，单张不超过 5 MiB；须填写中文或英文图注，并说明图片来源。上传后还要保存草稿。
4. 添加最多 30 篇论文，可从课题组论文库选择、用 DOI 查询或手动填写。核对作者、正式年份和本人贡献；入组前成果选择“入组前成果”。DOI 查询只是辅助填表，不证明本人署名或贡献。个人论文不会自动进入课题组首页精选或总论文库。
5. 点击“保存草稿”，再用“预览主页”检查文字和配图。准备好后点击“提交审核”；提交的是固定版本，之后继续改草稿不会改变已提交版本。退回时可看到审核意见，修改后再次提交。

登录邮箱不会自动写入新增的公开简介；“公开联系邮箱”是单独的选填字段。尚未保存的编辑可能随刷新丢失；多人/多标签同时操作导致版本冲突时，应先保留自己的文本，再刷新并核对最新草稿。

## 管理员怎样使用

1. 在“成员权限”中填写邮箱、选择对应成员和“成员”角色后开通；只有确需审核权限的账号才选择“管理员”。该操作只更新访问名单，不自动建立 Auth 用户，也不发送邀请邮件。需要另行把工作台入口交给成员，成员自行请求登录验证码。
2. 在“内容审核”中查看提交内容与当前获批版本，核对真实身份、论文署名、本人贡献、科研主张、配图来源及公开范围。内容不完整时填写原因后“退回修改”；确认后“批准此版本”。没有成员绑定的管理员可以审核和管理权限，不能代替任意成员编辑草稿。
3. 点击“发布已批准内容”，再打开“查看发布进度”。该操作会汇总当前所有获批快照，经过导出、图片校验、静态构建和检查后，才尝试部署网站。若构建或部署失败，查看失败记录后处理，获批内容仍保留；不要把“请求已接收”当作上线完成。
4. 工作流部署成功后，点击“检查线上版本”，确认对应记录显示“此版本正在网站展示”，再实际打开公开个人页核对。恢复旧内容时，先选择“恢复为待发布版本”，再执行一次发布并核对。

| 状态 | 含义 | 公开网站是否变化 |
| --- | --- | --- |
| 已保存草稿 | 私有草稿已保存 | 不变 |
| 待审核 | 固定版本已提交给管理员 | 不变 |
| 已批准／恢复为待发布版本 | 后台选定了允许公开的快照 | 尚未变化 |
| 发布任务已启动 | GitHub 已接受构建请求 | 不能据此判断 |
| 部署成功且线上版本匹配 | 公开 JSON 的版本 ID 与该提交相同，页面已核对 | 已更新 |
